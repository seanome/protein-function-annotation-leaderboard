  • kmerseek kmerseek 0.4.0 keys each index entry by its k-mer set, so two different sequences with the same k-mer set become one entry and the second is lost. In a regions-index pilot, 6 of 99_232 rows reported residues that are not at the target's own coordinates; the PR traces this to the key but has not confirmed it for each of the 6. In an index of 125 ribonucleases built on a later branch with the same key, 31 are missing under cys2 and 7 under cys_hp3.
    open · the number: 6 of 99_232 rows; 31 of the 125 ribonucleases · reported 10 Oct 2026 in seanome/kmerseek PR 141, seanome/kmerseek PR 148
    What to do: Rebuild every 0.4.0 index once kmerseek PR 141 is merged; it keys each entry by its sequence. Until then, a recall number from a 0.4.0 index is measured against a reference that may be missing targets.
    The source text, the run and its commit
    In the 2024-kmerseek-analysis regions-index pilot (kmerseek v0.4.0, protein20, k=5), 6 of 99_232 rows had a target_subseq that is not target[target_start:target_end].
    seanome/kmerseek PR 141
    Two different sequences with the same k-mer set get the same sum. So the second entry's hits came out with the first entry's coordinates and residues.
    seanome/kmerseek PR 141
    Not done: rebuilding the pilot index and rechecking the 6 rows. The two rows that are not anywhere in the target fit this cause, but I have not confirmed which earlier entry each of the 6 targets was merged into.
    seanome/kmerseek PR 141
    An index keys each entry by its k-mer set, so two sequences with equal sets collapse into one entry and only the first is stored.
    seanome/kmerseek PR 148

    seanome/kmerseek PR 148
