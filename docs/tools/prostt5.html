ProstT5 + Foldseek

Shape letters (3Di) predicted from the amino-acid sequence by the ProstT5 protein language model, then searched with Foldseek, so no AlphaFold model is needed.

Will it work for you?

  1. Is the closest same-family domain in the relative you will search at least 40% identical, for most of your proteins? If yes, Fmax here is 40–60% 0.139 (n = 563), 60–100% 0.209 (n = 1,289). If no, 20–30% 0.247 (n = 93), 30–40% 0.144 (n = 165). (Pfam truth set, raw calls, zebrafish (430 Mya) as the relative searched, setting shape letters from sequence; subsets with at least 30 true instances.)
  2. Do you have a GPU to predict the 3Di letters for your proteins? The run used one GPU for that step; its cost is not counted here.
  3. Can you spend about 0.109 core-hours per 1,000 proteins for each relative you search? That is the measured mean per relative; see "Cost per 1,000 queries" below.

Best Fmax and cost

Under the Pfam truth set, raw calls, zebrafish (430 Mya) as the relative searched, its best setting is shape letters from sequence (3di_from_seq): Fmax 0.223 over 2,435 true instances. Searching costs about $0.00486 per 1,000 queries (0.109 core-hours), for each relative searched.

Where it is strong and weak

Each line compares this setting with the best setting of any other tool on the same subset of the proteins, so the other tool's setting can change from line to line. Only subsets with at least 30 true instances are compared.

Where it is closest to, or furthest ahead of, the best other tool:

  • no same-family domain in the relative: Fmax 0.020 (n = 321); best other: HH-suite (hhsearch), single-protein profiles, 0.032.
  • identity 30–40% to the closest same-family domain: Fmax 0.144 (n = 165); best other: MMseqs2, three rounds, sensitivity 7, 3 rounds, 0.209.

Where it is furthest behind the best other tool:

  • regions 16–30 aa long: Fmax 0.000 (n = 271); best other: kmerseek, wwmj5, k = 11, 0.330.
  • regions 31–60 aa long: Fmax 0.032 (n = 420); best other: kmerseek, gbmr4, k = 21, 0.232.

Swiss-Prot features, raw calls, zebrafish, setting shape letters from sequence: best feature type active site, Fmax 0.278 (n = 176); worst membrane-spanning, Fmax 0.000 (n = 1,124).

What it compares

Shape letters (3Di) predicted from the amino-acid sequence by the ProstT5 protein language model, then searched with Foldseek, so no AlphaFold model is needed.

What it needs

  • sequence only: yes
  • 3D structure prediction: no
  • GPU: yes

Reference searched

3Di letters predicted by ProstT5 for the relative's proteome (Quest for Orthologs reference proteomes, release 2020_04), as a Foldseek database.

How to read its score

Bit score: higher ranks first. The E-value cutoff was 10.

Known failure modes

  • Proteins longer than 6,000 residues are skipped before the 3Di letters are predicted, and are listed in a skipped-proteins file.
  • Predicting the 3Di letters ran on one GPU (foldseek createdb --gpu 1). For the 998 queries that step is counted in the GPU column and the cost; for each relative's proteome it is a one-off database build and is not counted.

Cost per 1,000 queries

Setting 3di_from_seq, searching one relative (mean over the 15 relatives it searched): 0.109 core-hours reserved per 1,000 queries (16 cores for the task's wall time), measured on Sherlock. Peak memory 1.5 GB. That is about $0.00486 at $0.044625 per CPU-hour. Building its databases took 5.31 core-hours over 3 databases, plus 0.664 GPU-hours (1 GPU via --gres=gpu:1 (model not recorded)). A database is built once and reused, so this is not in the per-query cost. This covers the 3 database builds the task records hold; the search used 15 relatives.

The per-query cost counts the search only. The run recorded cost per tool and setting, summed over all relatives, so the cost for one relative is the mean.
