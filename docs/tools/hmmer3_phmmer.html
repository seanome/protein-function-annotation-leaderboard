phmmer

Amino-acid letters, one query protein against each protein of the relative, scored with a substitution matrix the way BLAST does but with HMMER's model of insertions and deletions.

Will it work for you?

  1. Is the closest same-family domain in the relative you will search at least 40% identical, for most of your proteins? If yes, Fmax here is 40–60% 0.252 (n = 563), 60–100% 0.308 (n = 1,289). If no, 20–30% 0.359 (n = 93), 30–40% 0.199 (n = 165). (Pfam truth set, raw calls, zebrafish (430 Mya) as the relative searched, setting default options; subsets with at least 30 true instances.)
  2. Are the features you care about longer than 60 residues? If yes, Fmax here is 61–120 aa 0.250 (n = 963), 121–250 aa 0.329 (n = 504), 251 aa or more 0.477 (n = 277). If no, 16–30 aa 0.042 (n = 271), 31–60 aa 0.095 (n = 420). (Pfam truth set, raw calls, zebrafish (430 Mya) as the relative searched, setting default options.)
  3. Can you spend about 0.417 core-hours per 1,000 proteins for each relative you search? That is the measured mean per relative; see "Cost per 1,000 queries" below.

Best Fmax and cost

Under the Pfam truth set, raw calls, zebrafish (430 Mya) as the relative searched, its best setting is default options (default): Fmax 0.333 over 2,435 true instances. Searching costs about $0.0186 per 1,000 queries (0.417 core-hours), for each relative searched.

Where it is strong and weak

Each line compares this setting with the best setting of any other tool on the same subset of the proteins, so the other tool's setting can change from line to line. Only subsets with at least 30 true instances are compared.

Where it is closest to, or furthest ahead of, the best other tool:

  • identity 20–30% to the closest same-family domain: Fmax 0.359 (n = 93); best other: MMseqs2, three rounds, sensitivity 7, 3 rounds, 0.337.
  • AlphaFold confidence (pLDDT) 50–70: Fmax 0.325 (n = 748); best other: MMseqs2, sensitivity 7, 0.310.

Where it is furthest behind the best other tool:

  • regions 16–30 aa long: Fmax 0.042 (n = 271); best other: kmerseek, wwmj5, k = 11, 0.330.
  • regions 31–60 aa long: Fmax 0.095 (n = 420); best other: kmerseek, gbmr4, k = 21, 0.232.

Swiss-Prot features, raw calls, zebrafish, setting default options: best feature type domain, Fmax 0.304 (n = 1,107); worst short motif, Fmax 0.000 (n = 190).

Known failure modes

failure_modes/hmmer3_phmmer.yaml

each row: how it fails, the number from the run that showed it, and the PR that reports it. Each quote is checked against its source on every push.

  • HMMER rounds E-values to two significant figures. Counting E ≤ cutoff on those rounded values, instead of E < cutoff, made the dark-set counts 2 to 222 lower. The dark set is the proteins that phmmer, jackhmmer and MMseqs2 all fail to place.
    open · the number: 2 to 222 · reported 13 Oct 2026 in seanome/2024-kmerseek-analysis PR 57
    Also on the cards of: jackhmmer
    What to do: Say whether each cutoff is strict (E < 1) or not (E ≤ 1), and use the same rule in every count that is compared.
    The source text, the run and its commit
    The pipeline's own dark set uses E ≤ cutoff, and HMMER rounds E-values to two significant figures. Under that rule the dark counts are 2 to 222 lower; Botryllus at E ≤ 10 is 2_039.
    seanome/2024-kmerseek-analysis PR 57, comment 6151921382
    The dark set is every protein in the query proteome that phmmer, jackhmmer and mmseqs2
    seanome/2024-kmerseek-analysis nextflow-runs/invertebrate-dark-set/main.nf at ec91da53

    Run: notebook 289, dark set and kmerseek reach at E < 1 vs E < 10 · commit 029c47a in seanome/2024-kmerseek-analysis

  • A call is the whole alignment, not the target's domain placed on the query, so a long alignment over repeats never lands on one repeat. On a 23-aa LRR_1 repeat, every MMseqs2 and phmmer call was 47 aa or longer, so none landed.
    open · the number: 47 aa or longer, on a 23-aa repeat · reported 13 Oct 2026 in seanome/2024-kmerseek-analysis PR 121
    Also on the cards of: MMseqs2, three rounds
    What to do: Place the target's domain on the query through the alignment before scoring. Notebook 280 switched to this rule; the leaderboard's own calls are still whole alignments.
    The source text, the run and its commit
    But every one of their calls is 47 aa or longer, so under half of it lies inside a 23-aa repeat, and the landing rule (at least half the call inside the domain) rejects it.
    seanome/2024-kmerseek-analysis PR 121, comment 6154499159
    a call is the whole alignment, not the target's domain projected onto the query, so long alignments over repeats never land on one repeat.
    seanome/2024-kmerseek-analysis PR 121, comment 6154499159
    Olga's decision (2026-10-14, before the test half was read): a call is the target domain placed on the query through the hit, and MMseqs2 runs one round (2067fa1; recorded in notebook 280's first cell).
    seanome/2024-kmerseek-analysis PR 121, comment 6169102356

    Run: the time-split pilot's tune half (notebook 280), rapeseed protein A0A078HBQ0, LRR_1 repeats 64-86 and 88-110 · commit 787bc31 in seanome/2024-kmerseek-analysis

  • Aligner calls run past the domain, because a call spans the whole aligned stretch. Over correct calls, they start a median 5 to 21 residues early. Over all calls, 45% to 60% start more than 100 residues early.
    open · the number: median 5 to 21 residues early; 45% to 60% more than 100 residues early · reported 15 Oct 2026 in seanome/2024-kmerseek-analysis PR 146, PR 3
    Also on the cards of: jackhmmer, MMseqs2, MMseqs2, three rounds, HH-suite (hhsearch), Foldseek, ProstT5 + Foldseek
    What to do: Read a call's ends as the alignment's ends, not the domain's. To score where a domain sits, place the target's domain through the alignment.
    The source text, the run and its commit
    Over correct calls, the median of call start minus true start is 0 for hmmscan, whose models define the Pfam truth, so the 1-based reading of truth and aligners holds. Aligners start a median 5 to 21 residues early, because a call spans the whole aligned stretch.

What it compares

Amino-acid letters, one query protein against each protein of the relative, scored with a substitution matrix the way BLAST does but with HMMER's model of insertions and deletions.

What it needs

  • sequence only: yes
  • 3D structure prediction: no
  • GPU: no

Reference searched

The relative's proteome (Quest for Orthologs reference proteomes, release 2020_04), as a FASTA file.

How to read its score

Domain bit score: higher ranks first. The E-value cutoff was 10.

Caveats of how this run was set up

  • None recorded for this run.

Cost per 1,000 queries

Setting default, searching one relative (mean over the 15 relatives it searched): 0.417 core-hours reserved per 1,000 queries (8 cores for the task's wall time), measured on Sherlock. Peak memory 4.9 GB. That is about $0.0186 at $0.044625 per CPU-hour. Building its databases for setting default: not measured (no task record holds a database build for this tool and setting).

The per-query cost counts the search only. The run recorded cost per tool and setting, summed over all relatives, so the cost for one relative is the mean.
