Known cases

Fourteen pairs of proteins whose shared job was proven in a laboratory, and what each of the nine tools on this board does with them. This page shows illustrations, not rates. The rates stay in Table 1, the leaderboard.

Data from 20 Oct 2026, commit 7eca428b (source)

In each case one protein is searched against the whole of UniProtKB/Swiss-Prot release 2026_03, and the question is whether the protein it shares a job with comes back, in the right place. Case 1, for example, searches the worm protein CED-9 against Swiss-Prot and asks whether human BCL-2 is among the hits. That is the opposite direction from Table 1, which searches human proteins against one relative's proteome.

Four words this page uses throughout. A call is one hit a tool reports, with the first and last residue of the query it covers. IoU (intersection over union) is the number of residues a call and the proven region share, divided by the number either one covers; the proven region is marked under the residues on every card. The site counts a call as correct at an IoU of 0.5 or more. An E-value is how many hits as good as this one a search of a database this size would be expected to turn up by chance, so smaller is better. A decoy is the same query with its residues reshuffled so that every pair of neighbouring residues still occurs as often as before. A hit counts only when the real query beats its decoy. Every query here has one decoy, shuffled with the random seed 1, so the same shuffle comes back on every rebuild.

14 cases, 24 query proteins (two cases search more than one protein), each searched by 9 tools at the setting Table 1 calls that tool's best. None of these searches has been run yet. Each result lands in its own place on the cards below as the runs finish; until then every mark reads not run and says why.

The four boxes

Each case sits in one of four boxes, and the box decides what counts as a right call.

  1. Box 1. Shared ancestor, same job. The two proteins descend from one ancestral protein and still do the same job. A call is right when it names the target's family and transfers its function.
  2. Box 2. Shared ancestor, new job. The two proteins descend from one ancestral protein, but the query protein has taken on a different job. A call is right when it names the family, and wrong when it carries the target's function across.
  3. Box 3. No shared ancestor, whole protein. The two proteins reached the same job from different ancestors, so there is no family truth. A call that names a family shared with the other protein is wrong, even though it points at a protein that does the same job; the card marks it wrong label and says what the call did get right.
  4. Box 4. No shared ancestor, short motif. A short stretch of the query protein copies a short stretch of a human protein. A call is right when it lands on those residues.

What a search costs

The cost on every card is core-hours × the price of a core-hour, plus GPU-hours × the price of a GPU-hour, the same arithmetic Compare two columns uses. Typing a different price in either box changes the cost on every card at once. Until a case has been run, the core-hours are the ones the Table 1 run measured for that tool against one relative's proteome, so the cost column is the only column on a card that is not from this page's own run. Swiss-Prot is larger than any one proteome, so those numbers are a floor.

One cost is left out. ProstT5 has to predict the 3-D shape letters of every query on a GPU before Foldseek can search with them, and the Table 1 run records that as a separate step: 0.221 GPU-hours for one database of 998 proteins, about 0.22 GPU-hours per 1,000 proteins, $0.22 at the price above. The cost column counts only the search, as the rest of the site does, so ProstT5's row is lower than the cost of annotating a new query with it.
